# MoonBit 生态索引

按**使用场景**组织的 MoonBit 包索引：把 mooncakes.io 的公开快照按场景归类，再把有完整方案的
场景分成**完整方案**（能直接定骨架）与**基础库**（提供单点能力）两层。产物有两种用法，打开就能用，
都不需要联网：

| 想做什么 | 用哪个 | 入口 |
| --- | --- | --- |
| 自己翻一翻、按场景选包 | **静态网站** | [在线站点](https://moonbit-ecosystem-index.pages.dev/) · [本地预览](#打开站点) |
| 让 AI 助手在开发时替你选包 | **选型 skill** | [安装](#安装) · [用法](#用法) |

本站定位是**导航，不是注册表的替代品**：版本历史、完整 API 文档与依赖关系不在站内复制，
页面里每个包名都直接指向 mooncakes 包页，需要细看时点过去即可。数据来自官方 API 的离线快照，
会滞后于注册表，页面顶部与页脚都标了采集与构建时间——依据见[数据来源与更新](docs/data.md)。

> 数字（包数、场景数、候选数）只存在于产物数据里，文档不复述，避免一采完就过期。

## 一、网站使用

### 打开站点

**在线**：<https://moonbit-ecosystem-index.pages.dev/>

**本地预览**（仓库内已含构建好的 `dist/`，不必先编译）：

```bash
cd app && moon run . -- --serve
```

打开 `http://127.0.0.1:8000`。必须走 HTTP：数据由前端 `fetch` 加载，直接双击以 `file://`
打开会被浏览器同源策略拦住。换端口用 `--serve 8080`，`Ctrl+C` 停止。

### 三个视图

站点是单页应用，路由由 URL hash 承担：

| 视图 | 地址 | 内容 |
| --- | --- | --- |
| 首页 | `#/` | 全部场景卡片，按「界面与应用 / 服务与数据 / 语言与工具」三组排列 |
| 场景详情 | `#/s/<场景 id>`，如 `#/s/gui` | 该场景的完整清单，完整方案与基础库全部列出，不截断 |
| 检索 | `#/search` | 全量模块的名称与描述检索 |

### 怎么读一个场景卡片

- 标题后是**完整方案 / 基础库**切换标签，点一下即切，不是折叠展开。
  「完整方案」指能接管程序结构、可直接选型的框架 / 引擎 / 运行时；「基础库」提供单点能力，
  由你组合。**没有完整方案的场景不设分层**，只有一个基础库清单并注明「需按需组合」——
  这是生态现状，不是数据缺失。
- 列表区**固定 5 行**，超出的裁掉，卡片底部有「查看全部 N 个」进入详情页。
- 卡片本身跳转到站内详情页；**包名**才跳转到 mooncakes 包页。
- 清单顺序是构建时算出的推荐次序，不是下载量排行，也没有「名次」宣称。排序依据见
  [分类与排序规范](docs/methodology.md)。

左侧分类导航常驻、独立滚动；窄屏下收成抽屉，点标题栏左侧的菜单按钮唤出，点遮罩、关闭按钮
或按 `Esc` 收起。

### 检索

顶部「检索」进入 `#/search`，输入即出结果，范围是快照里的全部模块。匹配按命中程度排序：
**包名全等 > 包名开头 > 包名包含 > 描述包含**，同程度按名称排列，最多展示前 200 条。
已 yanked 的包会带一个 `yanked` 标记，它们不进入场景推荐。检索不掺下载量，顺序可复现。

### 语言

中英文由三层决定，优先级从高到低：

1. URL 的 `?lang=zh` / `?lang=en`——带参数的链接本身就固定了语言，可直接分享；
2. 上次手动切换的选择（`localStorage`）；
3. 浏览器首选语言：以 `zh` 开头显示中文，其余一律英文。

标题栏右端的按钮上写的是**点它会切到的语言**（中文界面显示 `EN`，英文界面显示 `中文`）。
点击即时生效、不重载页面，检索页会保留当前查询；场景标题、简介与界面文案一起换，
包描述沿用注册表原文（多数为英文）——它是元数据，不翻译。

### 首页生态增长趋势

导语下方一张折线图，画**包数量**与**全生态累计下载量**随采集时间的变化：每次全量采集记一笔，
同一天重跑只覆盖当天那条。两条线量级差三个数量级，因此左右各一根纵轴（左蓝＝包数、
右绿＝累计下载），各自按数据范围缩放、**都不是从 0 起**，读的是变化幅度而非绝对高度；
图例给出最新值与较上次的增量，悬停任一点可读该次的完整数值。横轴按真实采集日期定位。

只有一条记录时不画折线，改为一句说明。这里放的是**全生态汇总**，不含任何单包下载量——
理由见[分类与排序规范 · 为什么站内不展示下载量](docs/methodology.md#为什么站内不展示下载量)。
窄屏会自动换成紧凑版，左右刻度仍完整可见。

### 反馈

标题栏右端的 GitHub 图标在任何视图里都可点；页脚末尾也把仓库地址与 `issues/new` 以文字写出，
便于复制转述。**指出一个包名就能定位规则**——场景判定词、显式收录与排除清单都在
`data/scenarios.src.json` 里。仓库：<https://github.com/lb091188/moonbit-ecosystem-index>

## 二、选型 skill 使用

`skills/moonbit-stack-selection/` 是同一份索引的另一种交付形态：给 AI 助手读的离线快照。
数据自带、不需要联网，也不需要跑脚本。做桌面 / 移动 / Web 后端 / CLI / 游戏 / LLM Agent 等
选型时，它会把需求先落到场景 id，再按「完整方案 → 基础库」给候选，并标出平台目标与边界。

```
skills/moonbit-stack-selection/
├── SKILL.md                 入口与硬规则（手写，不被生成覆盖）
└── references/              生成，一场景 1–2 份 md
    ├── scenarios.md         场景总表：分组、id、对应文件
    ├── <id>.md              索引页：完整方案全量 + 基础库按推荐次序列出
    └── <id>-libs.md         基础库全量分册（基础库较多时才有）
```

分两册是刻意的：索引页只有几 KB，助手读一个场景的代价远小于读全量索引；只有被要求穷举、
或索引页列出的基础库都不合适时才翻 `-libs.md`。

### 安装

整个目录放进助手扫描的 skills 目录即可，装一次，数据随后续 `git pull` 更新。

| 位置 | 目录 | 生效范围 |
| --- | --- | --- |
| 个人 | `~/.workbuddy/skills/`（WorkBuddy）、`~/.claude/skills/`（Claude Code） | 本机所有项目 |
| 项目内 | `<项目>/.workbuddy/skills/`、`<项目>/.claude/skills/` | 仅该项目，随仓库分发 |

```bash
git clone https://github.com/lb091188/moonbit-ecosystem-index.git
cp -r moonbit-ecosystem-index/skills/moonbit-stack-selection ~/.workbuddy/skills/
```

已经 clone 过、不想每次手动同步副本，改用软链，`git pull` 后立即生效：

```bash
ln -s "$(pwd)/skills/moonbit-stack-selection" ~/.workbuddy/skills/moonbit-stack-selection
```

装好后对助手说「用 moonbit-stack-selection 选一个桌面框架」即可触发。

### 用法

工作方式固定三步，完整硬规则写在 `SKILL.md` 里：

1. **先落场景，再谈选型**：需求是产品形态（「做个桌面小工具」）不是包名，先映射到场景 id，
   不确定时查 `references/scenarios.md` 的总表；
2. **查表，不凭记忆报包名**：一次只读 `references/<id>.md` 这一个场景，不要把整个
   `references/` 都读进来；索引页尾若指向 `<id>-libs.md`，没被要求穷举就不要往下读；
3. **给建议**：每个候选写清**形态**（谁负责画 / 谁负责调度）、**平台目标**
   （native / wasm / js / wasm-gc）、**代价**，最后单列「风险与未核实」。

几条最容易踩的硬规则：**不按下载量推荐**（序号是推荐次序不是热度）、**先确认 target**
（目标不匹配选型直接作废）、**「完整方案」≠ 生产可用**（研究性 / alpha 实现要标出来）、
**没骨架就说没骨架**、**不编 API**（快照没有函数签名，需要时去包页核对）。

没有本地文件、或想看最新在线版时，单场景页是
`https://moonbit-ecosystem-index.pages.dev/#/s/<id>`。站点是前端渲染的，直接抓页面拿不到数据；
纯文本可取仓库里的 raw md：

```
https://raw.githubusercontent.com/lb091188/moonbit-ecosystem-index/main/skills/moonbit-stack-selection/references/<id>.md
```

### 更新

数据由工作台「数据生成」就地重写，不往 `~/.workbuddy/skills/` 另外导出：

```bash
cd app && moon run . -- --build
```

生成后 `git add skills/ && git commit && git push`，GitHub 上的仓库即是发布版本；软链安装的
机器 `git pull` 即刷新，复制安装的需重新执行一次 `cp -r`。

## 三、维护者入口

改数据、跑构建、发布站点，都在 `app/` 的 MoonBit 工作台里：

```bash
cd app && moon run .              # 打开工作台（场景管理 / 包数据 / 数据更新 / 数据生成）
cd app && moon run . -- --fetch    # 只采集注册表快照，不开窗口
cd app && moon run . -- --build    # 只重算榜单并生成站点、报告与 skill
cd app && moon run . -- --serve    # 本地预览 dist/（默认 8000）
```

更新数据分两步：**先采集、再生成**，两步在工作台里是两个独立按钮，采集完必须再点一次生成。
全量采集是严格串行的，耗时以小时计，中途可停止（下载量与历史不会写半份；模块清单会先刷新，
详见[数据来源与更新](docs/data.md)）。
